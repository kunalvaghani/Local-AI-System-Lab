# Initial Risk Register

This register began in Stage 0 and is updated with evidence at each stage. A
planned mitigation is not an implemented control.

| ID | Risk | Likelihood | Impact | Current evidence | Planned response / owning stage |
| --- | --- | --- | --- | --- | --- |
| R-01 | 4 GB VRAM causes model load or context OOM | Medium | High | Stage 9 routes only available models, then retains exact profile admission and budget checks; measured VRAM spans 0 to 1,189 MiB for the pinned model | Retain reserves/OOM handling; require new evidence before activating each added model |
| R-02 | RAM/VRAM estimator diverges from real use | High | High | Constrained VRAM was underpredicted by 160.110 MiB and CPU-safe RAM by 375.172 MiB; reserves covered this sample | Calibrate each model/profile with repeated samples before broad accuracy claims |
| R-03 | Python concurrency blocks cancellation or shutdown | Medium | High | Stage 6 verifies queued/active cancellation, busy-worker queue expiry, bounded concurrency, and shutdown signaling; public agent calls still wait synchronously | Retain cooperative tests; expose external task control in API stage (15) |
| R-04 | Framework abstractions hide core runtime behavior | Medium | High | Stage 1 core uses stdlib protocols with no framework dependency | Keep core contracts framework-independent; ADR review at each integration |
| R-05 | Unrestricted tools expose host files/processes/secrets | Medium | Critical | Stage 5 permits only two read-only UTF-8 tools, requires exact grants/permissions, and rejects absolute, escaping, and non-allowlisted paths | Retain default deny; add OS isolation and adversarial suite (14) before risky tools |
| R-06 | Nondeterministic model output is misrepresented as replayable | Low | High | Stage 11 classifies model steps nondeterministic, stores input/output hashes, observes them without regeneration, and tests zero additional model calls during replay | Keep the boundary explicit; evaluation may compare quality later but must not relabel generation deterministic |

## Review rule

At each stage boundary, update evidence, add newly discovered risks, and change
likelihood/impact only when there is a stated reason. Closed risks remain in the
record with the verification that justified closure.
